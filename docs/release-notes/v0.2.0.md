# v0.2.0

## Breaking

**`GET /health` no longer returns a per-host map.** It reports counts:

```json
{"ok": true, "sites": 1, "verified": 1, "failed": 0, "pending": 0}
```

The per-host detail moved to `GET /health?detail=1`, which now **requires a
bearer token**. The reason is exposure: behind a Cloudflare Tunnel `/health` is
publicly reachable, and the host list was public with it. A check that reads
`keys` from the old shape will not find it — read `verified`, `failed` and
`pending`, or move to `?detail=1` with a token.

**A `key_location` in a subdirectory is refused at startup.** IndexNow scopes a
key file to the directory it is served from, so `https://example.com/assets/key.txt`
answers only for `/assets/...` and the engine refuses everything else with `422`.
It used to load, and `crawlping check` used to report it green, because only the
file's contents were compared. Point `key_location` at the host root, or leave it
out and the default already does.

**A URL outside the key file's directory is refused locally** as
`400 out_of_key_scope`, a reason that did not exist before. It is the same rule
enforced before the request instead of as a `422` from the engine. A deployment
that submits the whole host from a key file in a subdirectory was already broken;
it now says so instead of looking healthy.

**A per-host rate limit can answer `429 throttled`.** Ten requests back to back
per host, then one per second, refused locally without reaching the engine. A
caller that used to burst without limit will now see `429` from this instance
rather than from IndexNow. `throttled` is not `rate_limited`: the first means this
instance declined to spend the egress IP, the second means the engine is already
penalising it. Both carry `Retry-After`.

## Added

- **`crawlping init`** writes `config.yaml` and `<key>.txt`, then prints the
  deploy steps. `-shape docker|binary|tunnel` decides `listen:`, the line that
  costs the most to get wrong, and `-force` names the key file it orphaned.
- **`GET /submit?url=...`** submits one URL without a JSON body — IndexNow's own
  single-URL form. `url` may repeat.
- **`GET /metrics`** in the Prometheus text format: submissions and reasons,
  engine status and duration, URLs sent and skipped, guard refusals, key states.
  Host labels require a token, following the rule `/health` already followed.
- **`limits.max_urls_per_request` and `limits.max_body_bytes`** make one request's
  size configurable, up to IndexNow's own 10,000-URL ceiling; the default stays
  100. A pair that cannot carry its own batch is refused when the config loads.
- **A five-minute per-URL resubmission window** drops URLs sent recently and
  reports them in `skipped`, so a caller polling on a timer stops spending crawl
  quota on pages that did not change.
- **Engine concurrency is capped per site**, not only per instance, so one noisy
  site cannot hold every slot.
- **Three key states — verified, failed and pending** replace the old boolean. A
  check that never reached an answer is no longer reported as a broken key file.
- **`healthcheck -addr`** dials an address directly instead of parsing the config,
  so editing the config no longer moves the probe away from the running process.

## Fixed

- **Trailing bytes after the JSON object bypassed the body limit and were
  ignored.** `json.Decoder` stops at the end of the first value, so a small object
  followed by megabytes never reached `MaxBytesReader`, and a second object was
  silently dropped. The whole body is read now, the cap applies to what was sent,
  and trailing data is refused.
- **`check` reported a key file green while the engine refused it** whenever the
  file was on another host or in a subdirectory. That misclassification is gone
  from `check`, from `/health` and from the first real submission.

## Upgrading

1. If anything reads `keys` from `/health`, switch to the counts, or to
   `?detail=1` with a token.
2. Drop any `key_location` that is not at the host root, or move the file.
3. A caller that submits URLs from more than one directory with a key file in a
   subdirectory now gets `400 out_of_key_scope`; move the key file to the root.
4. A caller that bursts more than ten requests per host needs to handle
   `429 throttled`, the same way it already handles `rate_limited`.
